era of ai engineering

Prompt vs context vs harness vs loop vs graph engineering

The five eras of AI engineering. Each one builds on the last. None of them replaces what came before.

01

The input

01Prompt engineering

the original discipline

You type one message and hope it lands. The role, the rules, the examples, the format all have to fit inside that one block of text. Get it wrong and you start over.

  1. 1 One message in, one answer out
  2. 2 No memory between chats
  3. 3 No tools, just words
  4. 4 You drive every step

You write every word by hand.

02

The frame

02Context engineering

The model only sees a small window of text at one time. So the real job becomes picking what goes in that window. Notes, files, past chats, tool results — all curated by you. Everything else gets cut.

  1. 1 Pull from notes, files, tools, and past chats
  2. 2 Cut what does not fit
  3. 3 The unit of work is what stays in the window
  4. 4 Better context beats a smarter prompt

You curate what the model sees.

“Context engineering is the delicate art and science of filling the context window with just the right information for the next step.”

03

The engine

03Harness engineering

A model on its own is just a chatbot. Wrap it in tools, memory, rules, and helpers and it can run a real job. The harness is everything around the model that turns guesswork into reliable output.

  1. 1 The model plus tools, memory, rules, and helpers
  2. 2 Strip the parts off and you're back to a chatbot
  3. 3 Bolt them on and the model finishes real work
  4. 4 A weak harness is the bottleneck, not the model

You build the workshop the model runs inside.

Anthropic and the wider agent-building community call this the agent harness (or scaffolding) — everything around the weights that turns raw model capability into auditable, reliable software behavior.

04

The routine

04Loop engineering

You stop typing prompts. You build a loop that prompts the agent for you. The loop finds the work, picks a task, runs it, checks the result, and stops when the goal is met.

  1. 1 A loop runs on a timer or a trigger
  2. 2 It picks the task, does the work, and checks itself
  3. 3 You set the goal, the loop does the rest
  4. 4 The harness runs one agent, the loop runs the harness

The agent drives every step.

Osmani's five components of a real loop: automations (a schedule or trigger), worktrees (isolated parallel copies), skills (codified know-how), plugins/connectors (real tools via MCP), and subagents (independent verification) — plus shared external state so progress survives between runs.

05

The system

05Graph engineering

One agent that loops has one main road. Split the work into specialized nodes — each with its own prompt, context, tools, and private loop — and wire them together with edges, shared state, and routing rules, and the loop becomes a graph.

  1. 1 Each node is its own agent, carrying its own private loop
  2. 2 Nodes hand off only through shared state, never their own context
  3. 3 Routing rules decide where a pass — or a failure — goes next
  4. 4 A loop hides its failure modes; a graph puts them on paper

You stop trusting one agent to remember its own way back.

The shape isn't new — nodes, edges, and shared state have run production workflows for decades. What changed is the node: it can now be a full agent instead of a fixed function, and edges can route on a model's own verdict instead of hardcoded code.

The bottom line

Prompts did not die. Context did not die. The harness did not die. The loop did not die.
Each era adds a new layer. You still write prompts. You still curate context. You still build a harness. You still design the loop that runs it. Now you also draw the graph that connects several of them.
